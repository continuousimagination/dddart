# Public API and quickstart readiness (#102)

This integration branch implements #103–#107 in dependency order, starting from
main after #122. Version 1.0 is the first compatibility baseline. Authentication
remains optional, and release/publication work under #30 remains separate.

The child changes cover supported exports, serializer contracts, complete
quickstarts, capability documentation, and an executable documentation gate.
Each child is tested before its PR is merged into this branch. The parent PR
remains unmerged for review.

## #103 — supported exports

Removed the unused GraphTraverser, split SQL analyzer/schema generation into
`dddart_repository_sql/generator.dart`, and exposed only SQLite's builder
factory through `builder.dart`. Runtime imports keep runtime extension contracts.
`docs/PUBLIC_API.md` inventories every entrypoint and export, including intentional
SDK re-exports and generated-code support helpers.

Validation on Dart 3.13.7: SQL and SQLite package gates passed in CI mode
(SQLite: 127 tests); MySQL passed in local mode, including external regeneration
and custom-base compilation. MySQL service-dependent tests were not run for this
build-time export change. SQLite's external consumer also rejects five hidden
symbols through runtime imports and accepts the supported generator entrypoint.

## #104 — serializer configuration and errors

`Serializer<T, C>` makes format-specific configuration explicit; JSON uses
`SerializationConfig?` on every boundary. Shared helpers normalize JSON/input
validation failures, preserve already-typed exceptions, and retain causes/stacks.
Generated field decoding is separated from application constructors. Enum input
is validated explicitly. Removed unused duplicate generator templates and
regenerated the shipped REST models. `docs/SERIALIZATION.md` records defaults,
whole-config precedence, identity registry composition and error boundaries.

Validation on Dart 3.13.7: serialization 23, JSON 129, REST 371, SQLite 127,
and distributed events 58 tests passed with fresh generation. JSON's clean
consumer checks four wrong-config calls at compile time. The generated/handwritten
parity suite covers invalid input/config, codec failures, unencodable output,
original typed exceptions and application failures. REST package dry-run passed
after committing generated output; REST examples compile and both finite HTTP
examples run, including anonymous/public and protected operations.

## #105 — complete quickstarts

Added canonical outside-workspace applications for core events, generated JSON,
SQLite, MySQL, MongoDB, DynamoDB Local and public HTTP with a generated REST client
repository. Each includes a complete Git-pinned manifest, named files, clean
build_runner generation where needed, analysis/run commands, exact output and
cleanup. The JSON workflow also runs configuration and native-identity examples.
`docs/QUICKSTARTS.md` maps primary documentation and distinguishes illustrative,
browser, server and credential-dependent context. Public library comments and
package quickstarts link these complete workflows; root and website examples
include the canonical files verbatim. Refreshed the website's immutable code pin.

Validation: all seven applications resolved actual Git dependencies at
`56607ac8d3913b8e896ac03f8ecff58473d62ce2`, generated from clean state, analyzed and
ran outside the workspace on Dart 3.13.7. MySQL/MongoDB/DynamoDB used disposable
local containers. All 35 published file inclusions matched their executable
sources; 22 public entrypoints analyzed. Website check passed: 14 pages, 814
links/assets and 12 guides. #107 adds the permanent automated gate around these
same inputs; #100 still owns eventual hosted resolution proof.

## #106 — capability and support claims

`docs/CAPABILITIES.md` is the authority for all 18 packages: runtime/platform
composition, generation, service prerequisites, evidence and exclusions. It
separates CRUD/reference storage, narrow conditional writes, stronger IndexedDB
receipts, optional auth, and save/accept/delivery/outbox guarantees. Linked it from
package/root/API/website entrypoints. Corrected SQLite's Web claim, nonexistent
SQL mapper APIs, serialization ownership/dependencies and UUID-only event wording.
Removed obsolete pre-1.0 schema and fictitious MySQL 2.0 upgrade instructions;
qualified unverified database/cloud/device claims and deferred entity collections.

Validation: workspace inventory covers 18 public packages and 15 examples; every
matrix row/evidence link and canonical source inclusion verified. Website check
passed with 14 pages, 819 links/assets and 12 guides. This child changes
contract documentation only; the prior children's executable evidence remains
applicable. Release inclusion, SDK minimums and hosted package proof remain #30 work.

## #107 — executable documentation gate

Added an isolated documentation consumer gate that reuses Pub archive staging
and dependency/service policy from the shared validation inventory. It runs the
published command files, fresh generation, analysis and expected-output checks;
an explicit Git mode verifies the documented immutable revision. Scoped Dart
fences must match canonical inputs or a reviewed non-runnable/example-lane
classification. Drift checks also cover command/output inclusions, all 22 public
entrypoints and the 18-package capability matrix.

The nine workflows include the seven primary applications, additional complete
website modeling/configuration programs and a compile-only Slack server. Core
and JSON also compile/run as JavaScript under Node. Test CI adds the documentation
job and reuses existing MySQL, MongoDB and DynamoDB service jobs. Release tooling
under #100/#101 has documented commands and reusable canonical inputs; local/Git
verification does not claim hosted resolution or cloud/device coverage.

Validation on Dart 3.13.7 and Node 24.15.0: all nine workflows passed both local
archive and exact Git modes, including disposable local database services.
The source inventory checks 76 canonical inclusions and 265 explicitly classified
fragments. Website validation passed: 14 pages, 821 links/assets and 12 guides.
The staging helper passed analysis/formatting; workflow YAML parses with all ten
jobs intact. All 11 fault-injection tests passed, including real failures for
imports, constructors, parts and runtime output. GitHub's Test workflow is
manually disabled; these checks ran locally. The active Website workflow passes.
All task-owned database containers were removed after validation.
