# Concurrency readiness — issue #86

Integration branch for the transaction and conditional-write readiness work.

## Delivery order

- #87: execution-context transaction ownership for SQLite and MySQL.
- #88: portable conditional aggregate operations and shared conformance tests.
- #89: atomic SQL revision-checked persistence.
- #90: atomic MongoDB and DynamoDB revision-checked persistence.
- #91: atomic REST If-Match and generated-client integration.

Each child is implemented on its own branch and merged into this integration
branch after local validation. The parent remains open for human review.

1.0 is the first compatibility baseline; repository-owned consumers are updated
together. Existing IndexedDB receipt and reconciliation guarantees remain intact.

## Validation

Implementation and validation results will be recorded as each child completes.

### #87 — transaction ownership

Implemented on child commit `718f1d0`: a shared SQL execution-context coordinator
queues unrelated operations and joins intentional nested transactions with
rollback-only propagation. Failed BEGIN/COMMIT/ROLLBACK invalidates the connection;
late work cannot reuse an expired owner. Reads, writes and lifecycle operations
participate in the same scheduling.

Validated with Dart 3.13.7 and local MySQL 8 (`localhost:3307`, `test_db`):

- `dart tool/validation/validate.dart package dddart_repository_sql --mode=local`
- `dart tool/validation/validate.dart package dddart_repository_sqlite --mode=local`
- `dart tool/validation/validate.dart package dddart_repository_mysql --mode=ci`

All three integrated lanes passed generation policy, fatal-info analysis,
formatting, tests and publication dry runs. Regressions cover independent rollback
orders, reads/writes during rollback, nested failures, close/queued operations,
driver failure injection, escaped contexts and a generated SQLite aggregate graph.

### #88 — conditional aggregate contract

Implemented at `b90dfc9`, with obsolete enum-count fixture adjustment `ecff64b`.
`ConditionalAggregateRepository` provides single-aggregate versioned reads and
atomic conditional save/delete using the existing revision vocabulary. Both it
and the richer IndexedDB contract share `VersionedRepository`; receipt/uniqueness
requirements are not weakened. A detached in-memory reference and reusable
black-box adapter conformance suite define the server-side capability.

Validation on Dart 3.13.7:

- Core integrated package lane passed.
- IndexedDB integrated package lane passed, including VM/native Chrome and its
  cross-tab gate (96 tests; 3 platform-specific skips, with native suites run).
- Isolated archive consumers for core and IndexedDB passed.
- `dddart_events_example` example lane passed, including conditional writes.
- SQLite's clean generated consumer test passed against the final core API.

See `docs/CONDITIONAL_WRITES.md` for conditions, uncertainty and failure semantics.

Implementation: `8253362` (including direct-SQL fixture updates in `e1d26b6`).

Passed commands, using the Dart 3.13.7 SDK on `PATH`:

- `dart tool/validation/validate.dart package dddart_repository_sql --mode=local` — 89 tests.
- `dart tool/validation/validate.dart package dddart_repository_sqlite --mode=local` — 127 tests.
- `dart tool/validation/validate.dart package dddart_repository_mysql --mode=ci` — 221 tests, including real MySQL service tests.

- `dart tool/validation/validate.dart consumer dddart_repository_mysql`
- `dart test test/clean_consumer_generation_test.dart` from the SQLite package after explicitly adding the conditional capability to the external custom interface. The equivalent MySQL case passed in its package gate.

Package gates include regeneration, fatal-info analysis, formatting, tests,
and publish dry-runs. Shared contracts run for UUID/native/scoped identities.
Additional tests cover concurrent absent creates, complete graph rollback after
an injected child failure, coherent reads during another connection's write,
loser event retention, deferred outer-transaction publication, and uncertain
COMMIT handling. Conditional writes deliberately require a standalone transaction;
ordinary nested saves remain supported. Fresh-schema requirements and privileges
are described in `docs/CONDITIONAL_WRITES.md`. No prerelease schema upgrades or
cross-aggregate conditional transactions are claimed.

## #90 — atomic document revisions

Implementation: `d529a23` (core implementation `4558b0d`). Dart 3.13.7;
MongoDB 8.2.2 standalone on localhost:27017; DynamoDB Local 3.1.0 on
localhost:8000, shared in-memory mode. Tests use fresh databases/tables and
independent clients. No production credentials or AWS deployment was used.

Passed from the repository root, with Dart 3.13.7 on `PATH`:

- `dart tool/validation/validate.dart package dddart_repository_mongodb --mode=ci` — 106 tests.
- `dart tool/validation/validate.dart package dddart_repository_dynamodb --mode=ci` — 133 tests.
- `dart tool/validation/validate.dart consumer dddart_repository_mongodb`
- `dart tool/validation/validate.dart consumer dddart_repository_dynamodb`

Both package gates regenerate code, analyze with fatal infos, check formatting,
compile generated external consumers, run the real service suites, and pass
publish dry-runs. DynamoDB's incremental build cache initially failed to resolve
two test-library annotations; `dart run build_runner clean` from that package,
followed by the gate from the repository root, passed generation and all checks.

Coverage includes shared conditional contracts for UUID/native/scoped identities,
competing creates, coherent document/revision reads during writes, exact revision
equality, and event retention. Mongo tests exercise real unique-index and document
validation rejection and injected write-concern result failures. A real forwarding
HTTP proxy drops a DynamoDB response after the item is persisted: the caller gets
an uncertain outcome, retains pending events, and dispatches exactly one write.
The missing-table regression now awaits a request against an actually absent table.
Topology, permissions, fresh-storage setup, and the single-region/single-aggregate
boundary are documented in `docs/CONDITIONAL_WRITES.md`.

Implementation: `51f3063`, with validation fixture and formatting corrections
through `6a05236`. Dart 3.13.7; the same isolated MySQL 8.0 service described

- `dart tool/validation/validate.dart package dddart_rest --mode=local` — 309 tests.

The generated-client contract runs over real HTTP for UUID, native and scoped
identities. Response loss after a persisted write is uncertain, never retried,
and leaves events pending. Canonical strong validators, lists, weak/malformed
conditions, explicit unsupported shapes, absence, deletion/recreation, optional
428 enforcement, and incapable repositories are covered. REST-004 is retired
only after the MySQL cross-instance regression passed. No application outbox or
live-cloud deployment is claimed. The known older analyzer/build-runner
incremental annotation failure was cleared with `dart run build_runner clean`;
fresh generation and the full final package gate then passed.
